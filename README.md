# Telegram Quiz Manager

لوحة تحكم ويب عربية لإدارة بوت Telegram ونشر اختبارات **Quiz** (إجابة صحيحة واحدة)
تلقائياً في قناة أو عدة قنوات، وفق جداول نشر مخصّصة.

> الواجهة كلها من المتصفح. البوت يعمل في الخلفية وينفّذ الجدولة والنشر.

## 2. التشغيل السريع

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(48))"   # ضع الناتج في SECRET_KEY

python run.py            # أو: uvicorn app.main:app --host 0.0.0.0 --port 8000
```

ثم افتح <http://localhost:8000> وسجّل الدخول ببيانات `ADMIN_USERNAME` / `ADMIN_PASSWORD`
من ملف `.env`.

**وضع تجريبي:** إذا لم يوجد توكن للبوت (لا في `.env` ولا في الإعدادات) يعمل النظام كاملاً
دون إرسال أي رسالة فعلية — تُسجَّل العمليات في السجل كأنها نجحت مع وسم «تجريبي».
هذا مفيد لتجربة الجدولة.

### ربط البوت الحقيقي

1. أنشئ بوتاً عبر [@BotFather](https://t.me/BotFather) وخذ التوكن.
2. أضف البوت إلى القناة **كمشرف** مع صلاحيتي «نشر الرسائل» و«إدارة الاستطلاعات».
3. أدخل التوكن في **صفحة «الإعدادات» ← حالة البوت والتوكن ← حفظ التوكن**، أو ضعه في
   `TELEGRAM_BOT_TOKEN` داخل `.env` وأعد تشغيل الخادم. التوكن المحفوظ من اللوحة يتقدّم
   على قيمة `.env`.
4. من صفحة «القنوات» أضف القناة (مثال: `@my_channel` أو `-1001234567890`) واضغط «اختبار».

> **تخزين التوكن:** يُحفظ مشفَّراً في `data/secrets.json` بمفتاح مشتق من `SECRET_KEY`،
> ولا يُعاد عرضه في أي استجابة — تُعرض آخر 4 محارف فقط. عند حفظه تُعاد تهيئة البوت
> تلقائياً دون إعادة تشغيل الخادم. **تغيير `SECRET_KEY` يمنع فك تشفير التوكن المخزّن**،
> وحينها أعد إدخاله من الإعدادات.

## 5. ضمانات دورة حياة النشر

هذه القواعد مطبَّقة في الكود ومغطاة بالاختبارات:

1. **لا يُعتبر السؤال منشوراً إلا بعد تأكيد Telegram** — يُحدَّث إلى `published` بعد نجاح الإرسال فقط.
2. **لا يُعاد النشر عند إعادة التشغيل** — تُختار الأسئلة بحالة `ready` فقط، والمنشورة تُستبعد.
3. **لا يُحجز السؤال نهائياً قبل التأكيد** — تُسجَّل محاولة `pending` قبل الاتصال، ثم تُحدَّث.
4. **لا نشران متعارضان** — قفل `asyncio` + منع تكرار `pending` لنفس (السؤال، القناة).
5. **إعادة المحاولة للأخطاء المؤقتة فقط** — أخطاء الصلاحيات والمدخلات غير قابلة للإعادة.
6. **تنبيه واضح عند مشاكل الصلاحيات** — يُسجَّل الخطأ مع رمزه ويظهر في السجل واللوحة.
7. **حالة «نجاح ثم انقطاع قبل الحفظ»** — تُوسم الصفوف المعلّقة القديمة بـ `unknown` وتُعرض
   للمراجعة اليدوية بدل إعادة الإرسال أعمى.

### النشر اليدوي من القائمة (كلك يمين)

في **بنك الأسئلة** و**سجل النشر**، انقر بالزر الأيمن على أي صف لتظهر قائمة: معاينة،
**نشر الآن على قناة...**، تعديل، نسخ نص السؤال. اختيار «نشر الآن» يفتح نافذة لاختيار القناة
ثم يرسل السؤال فوراً عبر `/api/publishing/manual`.

> هذا المسار **يتجاوز منع التكرار عمداً**: إن كان السؤال قد نُشر سابقاً على نفس القناة
> فسيُرسل مرة أخرى، لأن الطلب بشري صريح. لكنه **لا يزال يمنع** النشر المتزامن لنفس
> (السؤال، القناة) أثناء التنفيذ، ويتجاهل حالة الإيقاف مثل زر «نشر سؤال الآن».
> النشر الآلي (الجدولة) يبقى محكوماً بقاعدة منع التكرار كما هو.

---

### النشر الجماعي لعدة أسئلة (بنك الأسئلة)

حدّد عدة أسئلة في **بنك الأسئلة** بمربّعات التحديد، ثم اضغط **نشر المحدد** في الشريط
الظاهر. اختر القناة المستهدفة وأكّد؛ يرسل الخادم الأسئلة **بالتتابع** إلى تلك القناة عبر
`/api/publishing/bulk`.

- الترتيب محفوظ كما حدّدته، وتُحذف التكرارات تلقائياً.
- فشل سؤال واحد **لا يوقف** البقية؛ يُعاد تقرير لكل سؤال (نجاح/فشل + السبب).
- مثل النشر اليدوي الفردي، هذا المسار يتجاوز منع التكرار عمداً لكنه لا يسمح بنشرين
  متزامنين لنفس (السؤال، القناة).
- يتطلب صلاحيتَي **بنك الأسئلة** و**النشر اليدوي الفوري** معاً.

> **مهم — تباعد الإرسال:** تيليجرام يحدّ سرعة الإرسال لكل قناة (نحو 20 رسالة في
> الدقيقة). لذلك يُرسل النشر الجماعي الأسئلة **بفاصل زمني** بين كل سؤال والذي يليه
> (الافتراضي 4 ثوانٍ)، وإن ردّ تيليجرام بـ «Flood control» ينتظر النظام المدة التي
> يطلبها ثم **يعيد المحاولة تلقائياً** بدل تسجيل فشل. قبل هذا الإصلاح كانت الدفعة
> الكبيرة تُرسل متلاصقة فيُقبل نحو 20 سؤالاً فقط ويُسجَّل الباقي فاشلاً.
>
> يُضبط الفاصل من **الإعدادات ← التباعد بين الأسئلة**: «الفاصل بين الأسئلة (ثانية)»
> و«أقصى انتظار عند الحظر». نافذة النشر الجماعي تعرض الوقت المتوقع للدفعة وشريط تقدّم،
> فلا تغلق الصفحة أثناء التنفيذ. وينطبق الفاصل نفسه على الدفعات المُجدولة
> (`questions_per_run > 1`) عند عدم تحديد فارق خاص بالجدول.

## 5.1 النشر عبر userbot (حساب مستخدم)

بجانب بوت `@BotFather`، يدعم النظام النشر عبر **userbot**: تسجيل دخول حساب تيليجرام
حقيقي (MTProto) عبر `api_id` و `api_hash` و جلسة مسجَّلة. هذا مفيد عندما لا يسمح
البوت بالنشر في قناة، أو عند توزيع النشر على أكثر من حساب.

### كيف أضيف حساباً؟

1. من [my.telegram.org](https://my.telegram.org) ← API development tools، خذ
   `api_id` و `api_hash`.
2. **الإعدادات ← حسابات userbot ← حساب جديد**: أدخل الاسم و`api_id` و`api_hash`
   ورقم الهاتف (بالصيغة الدولية).
3. اضغط زر **تسجيل الدخول** بجانب الحساب ← «إرسال رمز الدخول» ← أدخل الرمز الذي
   وصلك في تيليجرام (وأدخل كلمة مرور الخطوة الثانية إن كان الحساب محمياً بـ 2FA).
4. عند النجاح تُحفظ الجلسة ويصبح الحساب **مسجَّل الدخول**. اضغط «اختبار» للتأكد.

### كيف أوجّه القنوات؟

- **لكل قناة** (صفحة «القنوات» ← تعديل): اختر «نوع النشر» = `userbot` ثم حدّد الحساب،
  أو اتركه فارغاً لاستخدام الحساب الافتراضي.
- **افتراضياً لكل القنوات الجديدة** (صفحة «الإعدادات» ← نوع النشر الافتراضي).

### ضمانات وأمان

- تُخزَّن `api_id` و`api_hash` والجلسة **مشفَّرة** في `data/secrets.json` بمفتاح مشتق من
  `SECRET_KEY`، ولا تُعاد أبداً في أي استجابة (تُعرض masked فقط). ملف
  `data/userbot_accounts.json` يحتوي على البيانات الوصفية فقط.
- الجلسة تُمثّل صلاحية كاملة على الحساب؛ تعامل معها ككلمة مرور. تغيير `SECRET_KEY`
  يجعلها غير قابلة للفك، فسجّل الدخول من جديد.
- عند تعيين قناة على `userbot` دون حساب جاهز يفشل النشر بخطأ واضح في السجل بدلاً من
  النشر بهوية البوت — تجنّباً للنشر الخاطئ.
- مكتبة MTProto هي `kurigram` (فرع `pyrogram` النشط) وتُثبَّت من `requirements.txt`.
  إن لم تكن مثبّتة، تظهر رسالة تحذير في صفحة الإعدادات وتُرفض عمليات userbot بوضوح.
- جمع نتائج الاستطلاعات عبر userbot **لا يُغلق الاستطلاع** (قراءة فقط)، بخلاف البوت.

## 6. الأمان

- **كلمة المرور** بـ Argon2id (مع ترقية تلقائية عند تغيّر البارامترات).
- **الجلسات** ملفات موقّعة بـ itsdangerous، كوكي `HttpOnly` + `SameSite=Lax`، عمر محدود.
- **CSRF** رمز لكل جلسة يُتحقق منه في كل عملية مُعدِّلة.
- **الأسرار** (`SECRET_KEY`) من متغيرات البيئة فقط. **توكن البوت** يمكن ضبطه من اللوحة
  ويُخزَّن مشفَّراً (Fernet بمفتاح مشتق من `SECRET_KEY`) في `data/secrets.json` — لا يُكتب
  كنص مكشوف ولا يُعاد عرضه، ويبقى `TELEGRAM_BOT_TOKEN` في `.env` بديلاً اختيارياً.
- **التحقق من المدخلات** قبل أي كتابة، و**كتابة ذرّية** (ملف مؤقت + `os.replace`) مع قفل ملفات.
- **الإعدادات** ترفض أي مفتاح غير معروف بدل تخزينه بصمت.
- **صلاحيات متعددة المستخدمين**: كل `/api/*` يتحقق من صلاحية الحساب (`require_permission`)،
  وإعدادات النظام وإدارة المستخدمين مقصورة على دور `admin`. حساب المدير الأخير لا يمكن
  خفضه أو حذفه، وكل عملية على الحسابات تُسجَّل في سجل التدقيق.
- **واجهة الويب تعكس الصلاحيات**: تختفي من القائمة الجانبية أي تبويبة لا يملك المستخدم
  صلاحيتها، ويُخفى «آخر العمليات» (سجل التدقيق) في لوحة التحكم عن غير المدير. سجل النشر
  `/history` وواجهته `/api/history` مقصوران على المدير. صفحة الإعدادات تبقى متاحة للجميع
  لكن الألواح النظامية فيها تظهر للمدير فقط.

قبل النشر على الإنترنت: شغّل خلف HTTPS، اضبط `SESSION_COOKIE_SECURE=true`، واستخدم
`SECRET_KEY` عشوائياً طويلاً.

## 8. هيكل ملفات البيانات

```json
// data/questions.json
{"version": 1, "counter": 5, "questions": [
  {"id": "Q0001", "question": "...", "options": ["..."], "correct_option_id": 1,
   "explanation": "...", "category": "...", "difficulty": "easy",
   "status": "ready", "created_at": "...", "updated_at": "..."}
]}

// data/schedules.json
{"schedules": [{"id": "SCH001", "channel_id": "CH001", "enabled": true,
  "type": "times", "times": ["08:00","14:00","20:00"], "timezone": "Asia/Riyadh",
```

أنواع الجدولة: `daily` · `times` · `weekdays` · `interval` · `once` · `manual`.
طرق اختيار الأسئلة: `sequential` · `random` · `category`.

عند كل موعد ينشر الجدول **`questions_per_run`** سؤالاً (1–10) لا يتجاوز ما تبقّى
من `questions_per_day`، ويفصل بينها **`batch_interval_seconds`** ثانية (0–3600).
القيمة 0 تعني الإرسال دفعة واحدة دون فاصل.

الملفان `data/poll_results.json` و`data/poll_answers.json` يحفظان إحصاءات
التفاعل: الأول صف لكل استطلاع (أحدث قراءة للأعداد)، والثاني إجابة كل عضو
عندما يكون الاستطلاع غير مجهول.

## 8.1 صيغة ملف استيراد الأسئلة (JSON)

من صفحة **بنك الأسئلة → استيراد JSON** يمكنك رفع ملف، ويقبل النظام صيغتين:

1. **كائن فيه مفتاح `questions`** (المستحسن — نفس صيغة التصدير).
2. **قائمة أسئلة مباشرة** `[ {...}, {...} ]`.

### الحقول

| الحقل | مطلوب | الوصف | القيود |
| --- | --- | --- | --- |
| `question` | نعم | نص السؤال | 300 حرف كحد أقصى |
| `options` | نعم | قائمة الخيارات | بين 2 و10، بلا تكرار |
| `correct_option_id` | نعم | رقم الإجابة الصحيحة | يبدأ من **0** (أول خيار = 0) |
| `explanation` | لا | الشرح (التلميح) الذي يظهر بعد الإجابة | 500 حرف — وتيليجرام يقصّه إلى **200 حرف** |
| `category` | لا | التصنيف | الافتراضي `General` |
| `difficulty` | لا | الصعوبة | `easy` · `medium` · `hard` (الافتراضي `medium`) |
| `status` | لا | الحالة | `draft` · `ready` · `published` (الافتراضي `draft`) |

> لا تُدرج `id` أو `created_at` — يولّدهما النظام تلقائياً. وأي سؤال بحالة
> `ready` يصبح متاحاً للنشر مباشرةً من الجدولة.
>
> حقل **`explanation`** هو التلميح الذي يظهر للمشترك بعد إجابته. اجعله أقل من
> 200 حرف لأن تيليجرام يرفض ما زاد عن ذلك.

### الخيارات: صيغتان مقبولتان

```json
// (أ) نصوص مع رقم الإجابة الصحيحة
"options": ["HTTP", "DNS", "FTP", "SSH"],
"correct_option_id": 1,

// (ب) كائنات مع علامة على الخيار الصحيح
"options": [
  {"text": "DNS", "is_correct": true},
  {"text": "HTTP"},
  {"text": "FTP"}
]
```

### ملف كامل (انسخه وعدّله)

```json
{
  "version": 1,
  "questions": [
    {
      "question": "ما المنفذ الافتراضي لبروتوكول SSH؟",
      "options": ["21", "22", "23", "25"],
      "correct_option_id": 1,
      "explanation": "SSH يعمل افتراضياً على المنفذ 22.",
      "category": "Networking",
      "difficulty": "easy",
      "status": "ready"
    }
  ]
}
```

يوجد ملف جاهز في `examples/questions.sample.json`.

### سياسة التكرار

يُكتشف السؤال المكرر بمطابقة **نص السؤال** (دون حساسية لحالة الأحرف). اختر:

- `skip` (الافتراضي): تجاهل المكرر.
- `update`: حدّث السؤال الموجود.
- `create`: أضف نسخة جديدة دائماً.

### الاستيراد عبر API

```bash
curl -X POST http://localhost:8000/api/questions/import-file \
  -H "X-CSRF-Token: $CSRF" -b "tqm_session=$SESSION" \
  -F "file=@examples/questions.sample.json" -F "duplicate_policy=skip"
```

### ماذا يحدث للأسئلة الخاطئة؟

الأسئلة الصحيحة تُستورد، والخاطئة **لا توقف** العملية؛ يعيد التقرير عدد
`imported` و`updated` و`skipped` و`failed` مع أول 20 خطأ وسبب كل خطأ.

## 9. إحصاءات التفاعل وقيود Telegram

تعتمد صفحة **الإحصائيات** على واجهة Telegram Bot API، وهناك قيدان مهمّان
يجب فهمهما قبل الاستخدام:

1. **قراءة الأعداد تُغلق الاستطلاع.** لا يوفّر Telegram أي طريقة لقراءة
   أعداد التصويت دون استدعاء `stopPoll`، وهذا الاستدعاء يُغلق الاستطلاع
   نهائياً. لذلك لا يجمع النظام النتائج تلقائياً بعد كل تصويت (وإلا توقف كل
   اختبار فور نشره)، بل يجمعها عند الطلب من زر **«جمع النتائج الآن»** أو عبر
   مهمة مجدولة (اختيارية) بعد أن ينتهي التصويت.

2. **تتبّع كل عضو يحتاج استطلاعاً غير مجهول.** إشعار `poll_answer` الذي يحمل
   هوية المصوّت لا يصل للبوت في الاستطلاعات المجهولة. لتتبّع تفاعل كل عضو
   لحظياً، ألغِ خيار «استطلاع مجهول الهوية» في الإعدادات (سيكون التصويت علناً).

عملياً: استخدم الجمع اليدوي/المجدول للأعداد الإجمالية، واختر التصويت العلني
إذا أردت معرفة من أجاب بماذا.
